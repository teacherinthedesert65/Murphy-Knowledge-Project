PHP2Shell: AI and the Race to Secure the Web

AI-assisted research has helped expose serious weaknesses in widely used web software. The lesson reaches beyond any single programming language.

Published October 21, 2026 • Information checked on publication day

What is confirmed?

On October 21, 2026, PHP released security updates addressing CVE-2026-109618 and CVE-2026-109619, collectively known as PHP2Shell. Both are rated critical. They can permit remote code execution without an attacker logging in. In plain language, a vulnerable server could be tricked into running an outsider’s instructions. [1]

Where did the software go wrong?

Both flaws concern memory management inside PHP. One involves handling exhausted memory while internal data is incompletely initialized. The other involves internal state that remains accessible after its underlying memory has been freed. A later operation can mistakenly trust that stale state. [1]

What role did AI play?

Wiz reports using Wiz Atlas, Gemini 4 Argon and GPT-5.6 Sol during discovery, testing and remediation research. It credits collaboration with PHP maintainers, Calif and OpenAI. The researchers describe AI as helping turn complex, longstanding weaknesses into demonstrable security failures. [2]

That is evidence of AI-assisted security research, not proof that a model independently performed every step. Researchers still tested the findings, coordinated disclosure and worked with maintainers on fixes. Credit should reflect that combined work. [2]

Why this belongs on MKP

This case links machine intelligence to the hidden infrastructure people use daily. A promising tool for finding defects can also make those defects easier to exploit. MKP’s interpretation is that discovery speed must be matched by the ability to validate reports, distribute fixes and maintain deployed systems.

Keep the scale in perspective

PHP’s widespread use helps explain the concern, but a technology’s market share is not a count of successfully compromised websites. Exposure, exploitability and confirmed compromise are different claims. A severity score describes the vulnerability; it does not establish that every site has been attacked.

What administrators should know

PHP identifies fixed releases as 8.5.12, 8.4.27, 8.3.36 and 8.2.35. Administrators should follow the official advisory and their hosting or operating-system vendor’s instructions, including vendor-provided backports. PHP says partial mitigations do not replace updating. These versions describe the October 21 release; consult current vendor guidance for later updates. [1]
